# 15 — Тесты ядра (`core/tests/`)

pytest-набор, доказывающий свойства ядра: корректность чистки, анти-утечку, жёсткие ограничения,
штатный отказ и воспроизводимость. «pytest (пайплайн + ограничения + отказ) + ruff — доказательство
воспроизводимости». Тесты бегут на **мини-выборке** фикстур — полный
прогон занимает секунды, без сети и без реального датасета.

## Scope

| | |
| --- | --- |
| **Содержит (covers)** | тесты чистки сентинелов; анти-утечка ЛИМС ≤ 4 ч (`available_ts = sample_ts + 4 ч`); границы движка ограничений [[06-constraints-engine]]; отказ ([[10-refusal]]) по каждой причине `RefusalReason`; детерминированность повторного прогона; свойства Парето (недоминируемость); фикстуры на мини-выборке; реакция на смену задания по качеству |
| **НЕ содержит (does NOT cover)** | интеграционные тесты API (backend/08); тесты пайплайна обучения как такового (data-pipeline/10-tests.md — соседний набор для того же pytest-прогона); нагрузочные тесты |

## Матрица тестов

| Модуль теста | Что проверяет | Ключевое утверждение |
| --- | --- | --- |
| `test_clean_sentinels.py` | чистка сентинелов (совместно с data-pipeline/10) | {307, 251, 252, 240} → `null` + `quality_flag = sentinel`; ни одно «сырое» значение сентинела не попадает в признаки и метрики |
| `test_antileak_lims.py` | анти-утечка ЛИМС ≤ 4 ч | ни одного значения ЛИМС в выборке с `ts < available_ts`; `available_ts = sample_ts + 4 ч` |
| `test_constraints_engine.py` | границы [[06-constraints-engine]] | сера ≤ 10 мг/кг; T95 ≤ 360 °C; ЦЧ ≥ 51/49; плотность 820–845 / 800–845; доли = 100 %; присадка ≤ 3 %; p2/p98-диапазоны; вердикт pass/violate + причина |
| `test_refusal.py` | отказ [[10-refusal]] | каждая причина `RefusalReason` срабатывает на своём триггере; приоритет причин; инвариант карточки refuse |
| `test_pareto.py` | свойства фронта [[08-pareto-front]] | недоминируемость ранга 1; детерминированный порядок; политика безопасности выбирает maximin-точку |
| `test_determinism.py` | воспроизводимость прогона | один seed → идентичный `RunReport` (кроме полей времени) |
| `test_scenario_sensitivity.py` | «нежёсткость» сценариев [[13-scenarios]] | смена задания (лето ↔ зима) меняет `checks`/`actions`; смена входного качества меняет рекомендацию |

## Фикстуры на мини-выборке

```python
# core/tests/conftest.py
@pytest.fixture(scope="session")
def mini_dataset(tmp_path_factory) -> Path:
    """Синтетическая мини-выборка: 3 суток 10-минутной сетки (432 точки), 12 тегов
    (управляемые P8/T11/F19 + ключевые Q21, T5), 6 меток ЛИМС, сентинелы {307,251,252,240}
    в двух каналах, один залипший канал. Схемы — как в data-store (A.1/A.2 [[07-run-report]]).
    Формирует data/processed/*.parquet в tmp_path — реальные каталоги не трогаются."""

@pytest.fixture(scope="session")
def mini_models(mini_dataset, tmp_path_factory) -> ModelRegistry:
    """Мини-модели LightGBM (quantile P10/P50/P90), обученные на фикстуре за < 5 с,
    + conformal-параметры; manifest [[08-model-artifact]] с trained_on_range = период фикстуры.
    Реестр в tmp_path — ядро загружает его как обычный (P5), тесты не тренируют «в тесте агентов»."""

@pytest.fixture(scope="session")
def seeds() -> dict[str, int]:
    """Фиксированные сиды всех сценариев: normal/quality_risk/bad_data/sour_crude/stale_lims = 42."""
```

Правила фикстур: sessionscope для дорогих артефактов; всё в `tmp_path`; детерминированная
генерация синтетики (под сидом) — сами фикстуры тоже воспроизводимы.

```

## Ограничения: таблица случаев

| Случай | Вердикт ожидаемый |
| --- | --- |
| сера 10,4 мг/кг | `violate: sulfur_max` |
| T95 = 361 °C | `violate: t95_max` |
| ЦЧ 50,4 (летнее) | `violate: cetane_min_summer` |
| ЦЧ 49,5 (зимнее) | `pass` (зимний порог 49) |
| плотность 818 кг/м³ (лето) | `violate: density_range` |
| доли 0,86 + 0,12 + 0,00 | `violate: blend_shares_sum` (≠ 100 %) |
| присадка 3,5 % | `violate: additive_max` |
| P8 = 345 °C при p98 = 344 | `violate: model_range_p2p98` (пометка «допущение») |
| все пороги соблюдены | `pass` |

## Отказ: тест по каждой причине

@pytest.mark.parametrize("reason,trigger", [
    ("stale_lims",              FaultInjection(lims_age_hours=60.0)),          # > 52 ч
    ("wide_interval",           FixtureTag.widen_conformal(interval_width=6.0)),
    ("out_of_training_domain",  FixtureTag.t_point_outside_trained_range),
    ("no_feasible_variant",     FixtureTag.raw_sulfur_above_limit),            # вся решётка отбракована
    ("sensor_fault",            FaultInjection(stuck_tags=["24-2000.W4"])),
])
def test_refusal_reason(mini_models, reason, trigger):
    """Ожидание: RunStatus.refused; refusal.reasons содержит reason; details[] содержит числа
    из контекста; explanation собран шаблоном [[10-refusal]]; карточка не содержит actions."""
def test_refusal_is_not_failure(...):
    """refused ≠ failed: refused — нормальное завершение конвейера (код 0 в CLI [[14-cli]]),
    failed — только исключение."""
```

Отказ «плохие данные» (сценарий `bad_data` из [[13-scenarios]]: сентинелы + старый ЛИМС)
проверяется сквозным прогоном пяти агентов — ровно то, что показывает `make demo`.

## Детерминированность повторного прогона

```python
def test_run_is_reproducible(mini_models, seeds):
    """Прогон quality_risk дважды с seed = 42:
      1) RunReport.diff() пуст, кроме created_at/started_at/finished_at/duration_ms/run_id;
      2) решения и числа идентичны: «при одинаковом состоянии системы должны воспроизводиться
         одно и то же решение и одинаковые численные результаты»[^repro];
      3) Парето-фронт и `pareto_rank` совпадают попозиционно;
      4) смена seed'а меняет только идентификаторы/тайминги, не числа решения."""
```

Чек-лист источника детерминизма (delivery-infra/05-seeds-reproducibility.md): запрет скрытых
случайностей и параллелизма с гонками; хэши данных и версии — в отчёте; `n_jobs` инференса
не влияет на результат.

## Запуск и CI

```bash
make test        # pytest core/tests + data-pipeline тесты одним прогоном
uv run pytest core/tests -q            # только ядро
uv run pytest core/tests -k refusal    # подмножество по имени
```

Параллельность тестов допустима (каждый тест в своих `tmp_path`); гонки исключены отсутствием
общего состояния. Ruff — отдельной целью `make lint`.

## Правила дизайна

> [!warning] Ключевые правила
> 1. Тесты — на мини-выборке фикстур: секунды, без сети, без реального датасета.
> 2. Каждое требование продукта, которое можно сломать молча (утечка, ограничения, отказ), — тест.
> 3. Отказ проверяется и юнит-уровне (причина), и сквозном (сценарий `bad_data`).
> 4. Детерминизм — тестом на дифф отчётов, а не «мы старались».

[^lims]: Правило задержки публикации ЛИМС: «метка времени = момент отбора пробы; до публикации результата
проходит до 4 часов (транспортировка + анализ). При исторической валидации результат ЛИМС доступен
системе только через ≤ 4 ч после метки — иначе утечка будущего».
[^repro]: Правило воспроизводимости: «При одинаковом состоянии системы должны воспроизводиться
одно и то же решение и одинаковые численные результаты».
[^nonrigid]: Свойство сценариев: «Сценарии не "жёсткие": результат должен меняться при
изменении входов — и качества сырья, и задания на качество продукции».
