# 04 — Агент качества (роль `quality`, step 1)

## Scope

Второй агент конвейера: прогноз показателей товарного качества квантилями P10/P50/P90,
оценка риска выхода за спецификацию, приоритезация источников качества и SHAP-объяснение.

**Покрывает:** инференс по целям [[01-enums|QualityTarget]] (сера, T95, ЦЧ, плотность D15); конформные
интервалы; `spec_risk`; выбор значения по приоритету ЛИМС > ПАК > ВАК > модель; запрос top-k
признаков у SHAP-сервиса ([[11-explain-shap]]).
**Не покрывает:** обучение моделей — граница P5 ([[02-model-registry]]); генерацию круток
([[07-agent-optimization]]); решение об отказе ([[09-agent-orchestrator]], [[10-refusal]]);
поля DTO — только [[03-quality-assessment]].

> [!quote] Роль агента качества
> «Оценивает текущее/прогнозное качество; выявляет риск выхода за
> спецификацию; оценивает влияние изменения режима. Прогноз показателей качества, риск
> нарушения, уверенность/качество данных.»

## Четыре цели прогноза

| target | Единица | Норма спецификации | Данные для контроля | Модель |
| --- | --- | --- | --- | --- |
| `sulfur` | мг/кг | ≤ 10 | ЛИМС отбор 2, n = 1462 (ритм 24 ч); ПАК 10-мин | LightGBM quantile P10/P50/P90 + CQR; what-if сдвигает L2-локализатор с monotone (Q21 в фичах нет) |
| `t95` | °C | ≤ 360 | ЛИМС 95%.T, n = 1292 | последняя проба + сдвиг месяца; бустинг на holdout 2026 проиграл persistence |
| `d15` | кг/м³ | 820–845 летнее / 800–845 зимнее | ПАК только с 05.03.2025; ЛИМС редкая | модель (лаборатории почти нет); в текущем бандле не обучалась |
| `cetane` | пункт | ≥ 51 летнее / ≥ 49 зимнее | ЛИМС, 42 замера (~29 суток) | без бустера: мало меток, широкая неопределённость |

> [!quote] Решение по цели t95
> «T95 не вычислим (ссылается на несуществующую точку ЛИМС). LightGBM quantile на holdout 2026
> проиграл последней пробе → в рантайме бейзлайн persistence + month offset, не более слабый бустер.»

> [!quote] Спецификации целей
> «`QualityTarget` ([[01-enums]]) | `sulfur` (мг/кг, ≤ 10); `t95` (°C, ≤ 360); `d15` (кг/м³, 820–845 / 800–845 зимнее); `cetane` (≥ 51 летнее / ≥ 49 зимнее)».

Горизонт прогноза — 0–3 ч, шаг рекомендаций 15–60 мин (требование детерминированности
цикла рекомендаций). Сама величина задержки — явное допущение:

> [!quote] Решение по задержке прогноза
> «**Задержку 0–3 ч из сырых корреляций не вытащить** (закрытый контур АСУ + автокорреляция,
> максимум при лаге 0). Решение: задержку задаём как явное модельное допущение, не притворяемся,
> что «нашли» её в данных.»

## Приоритет источников: ЛИМС > ПАК > ВАК > модель

> [!quote] Правило приоритета источников
> «**Приоритет по качеству**: ЛИМС → ПАК → расчётные/виртуальные анализаторы. Если значения
> расходятся, лабораторный результат считается контрольным фактом. Необходимо учитывать,
> что ПАК могут периодически выходить из строя.»

| Приоритет | Источник [[01-enums|DataSource]] | Роль в оценке | Ограничение использования |
| --- | --- | --- | --- |
| 1 | `lims` | контрольный факт: последний доступный замер (с учётом «+4 ч») | доступен ~раз в сутки; при age > порога — вердикт [[03-agent-data]] |
| 2 | `pak` | оперативный контроль уровня и тренда | поточечно с ЛИМС не сверять |
| 3 | `vak` | расчёт T50/T90 — фичи и бейзлайн; CFPP с калибровкой смещения ~ −11 °C | часть формул не вычислима (T95) |
| 4 | модель | прогноз после крутки; единственный источник для целей без свежей лабы | только активный артефакт [[08-model-artifact]] |

Поточечная несогласованность ПАК и ЛИМС — установленный факт, а не гипотеза:

> [!quote] Результат сопоставления источников серы
> «Три источника серы согласованы по уровню (~8.4–8.6 мг/кг в среднем), но **поточечно ПАК и
> ЛИМС не коррелируют** (r ≈ −0.003): ПАК — только для оперативного контроля, ЛИМС — контрольный
> факт; поточечную сверку не строить.»

## Выход в карточку: маппинг

Оценки агента — источник всех «чисел качества» карточки рекомендации ([[04-recommendation]]):

| Блок карточки | Откуда берётся |
| --- | --- |
| «Проблема / риск» | `risks[]`: `{target, limit, limit_value, p50, p10, p90, spec_risk}` — по каждой цели |
| «Ожидаемый эффект» | `effects[]`: `baseline_p50 → action_p50`, p10/p90, `margin_to_spec` — считает [[07-agent-optimization]] на тех же моделях |
| «Уверенность» | ширина интервала `interval_width` + свежесть из [[03-agent-data]] (предупреждение о старых данных) |
| «Объяснение» | `shap_top_k` + `notes` шага; текст формулирует оркестратор/нарратор, числа не порождает |

## Батч-оценка «что если» — граница с оптимизацией

Прогноз для кандидатных круток и what-if — тот же инференс по тем же `LoadedModel`
из [[02-model-registry]]: модели уже в памяти, батч-прогноз сетки вариантов и синхронный
what-if укладываются в SLA < 50 мс. Агент качества отвечает
за baseline-оценку, приоритет источников и конформные интервалы; переиспользование моделей
оптимизатором — переиспользование, а не дублирование логики (P2: «вызов, не дублирование»).

## Приёмочные проверки (для [[15-tests]])

1. Для одного входа и одной модели: p10 ≤ p50 ≤ p90, ширина и `spec_risk` детерминированы.
2. При свежем ЛИМС baseline = ЛИМС; при age > порога — источник понижается по цепочке
   приоритетов и это видно в `notes` шага.
3. `interval_width` пересекает границу спецификации ⇒ в выходе агента флаг для отказа
   `wide_interval` (не карточка — решение за оркестратором).

[^2]: По истории данных тег `24-2000:D15` (кг/м³): 75 455 значений, только с 2025-03-05 10:20.
[^3]: По истории данных CFPP исправленный систематически занижен относительно ЛИМС (−17 vs −6.2) — требует калибровки.
