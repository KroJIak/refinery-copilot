# 05 — Построение признаков (`features/build.py`)

> [!note] Назначение
> Собирает обучающие строки `quality_datasets/{target}.parquet` (P4): агрегаты телеметрии
> перед отбором пробы, лаги, возраст лаборатории, наработка катализатора, сезон и ВАК-фичи —
> плюс таргет с соблюдением анти-утечки. Потребитель — обучение моделей (06-train-quantile)
> и рантайм ядра (агент данных собирает те же признаки на `t_point`).

## Scope

**Содержит:** окна усреднения телеметрии перед отбором пробы; лаги 0–18 шагов × 10 мин (0–3 ч,
явное допущение); возраст ЛИМС/ПАК как фича; наработка катализатора с якорями по просадкам T5
апр-2024/май-2026; месяц/сезон; ВАК T50/T90 как фичи, CFPP с калибровкой смещения; обработку
дублей каналов r ≥ 0.96; правила анти-утечки на уровне признаков.

**Не содержит:** обучение и калибровку моделей (06/07), валидацию (08), решение об отказе,
изменение таргетных определений (канон [[01-enums]]).

## 1. Таргеты и точки сборки

Обучающая строка привязана к **лабораторному замеру**: `sample_ts` — точка сборки фич, таргет —
значение показателя из ЛИМС (контрольный факт; приоритет ЛИМС → ПАК → ВАК, [[03-sync-freshness]] §5).

| Цель (QualityTarget) | Таргет | n | Особенность |
| --- | --- | --- | --- |
| `sulfur` | ЛИМС Mg.Sulfur «ГО, отбор 2», мг/кг | 1 462 | медиана 8.60; >10 мг/кг — 15.7 % замеров; выбросы 107/120/2120 → маска |
| `t95` | ЛИМС 95%.T | 1 292 | ВАК-формула T95 **не вычислима** (нет точки `24-2000.Pipeline`) → собственная модель[^t95] |
| `d15` | ПАК D15 (с 05.03.2025) + ЛИМС D15 | 75 455 + 1 015 | пустой диапазон 2023–2024 по ПАК легален |
| `cetane` | ЛИМС CetaneNumber | 42 | ~29 суток между замерами — ЦЧ-строки почти всегда `stale` по freshness |

Мягкий таргет серы: ПАК `24-2000:Mg.Sulfur` (10-минутная сетка) используется для промежуточной
валидации **по уровням и трендам**, не поточечно (r ПАК↔ЛИМС ≈ 0; правило продукта).

## 2. Окна-средние перед отбором пробы

Для каждого рабочего канала — агрегаты телеметрии по окнам, заканчивающимся в `sample_ts`
(только `quality_flag = 'ok'`; доля не-ok точек в окне — отдельная фича-«качество канала»):

| Окно | Агрегаты | Обоснование |
| --- | --- | --- |
| 30 мин | mean, std | мгновенный режим |
| 60 мин | mean | сглаженный режим |
| 180 мин | mean | режим за горизонт задержки 0–3 ч |

Агрегаты берутся по **«истинным» каналам** по поведению (T5/T6/T11 — температура; F19/F17/F26 —
расход сырья; P13/P3 — давление; T55 — выход печи П-3; F65 — прокси расхода нефти ~900 т/ч),
а не по справочнику КИП (17 из 26 кодов расходятся).

## 3. Лаги 0–18 шагов (допущение задержки 0–3 ч)

> [!quote] Требование к задержке
> «Задержка «воздействие → качество»: **0–3 часа**, величину желательно найти из данных самостоятельно».

Факт из анализа данных: из сырых 10-минутных корреляций задержка
**не идентифицируется** — кривые лаг-корреляций плоские, максимум |r| при лаге 0 (T11↔Q21 r = −0.695),
потому что внутри контура работают АСУ с обратной связью и оба ряда серы автокоррелированы.

Решение: не фиксировать лаг, а подать **весь диапазон** — значения каналов при лагах
0, 3, 6, 9, 12, 15, 18 шагов (0–180 мин) — и отдать выбор модели:

```python
def lagged_values(long: pl.DataFrame, tag: str, sample_ts: datetime,
                  lags: tuple[int, ...] = (0, 3, 6, 9, 12, 15, 18)) -> dict[str, float]:
    """f'{tag}_lag{k}' = value(ts = sample_ts − k·10 мин), k·10 мин ∈ 0..180 мин (0–3 ч — допущение)."""
```

Ограничение интерпретации: важность лагов — гипотеза о задержке, не измерение; санити-чек
чувствительности ~0,3 мг/кг серы на 1 °C температуры.

## 4. Дубли каналов r ≥ 0.96 — обработка

Кластеризация по парной корреляции на чистой истории; в фичи идёт **один представитель кластера** —
канал с минимальной долей не-ok флагов и без потолков (правило [[02-clean-sentinels]]):

| Кластер | r | Представитель | Выброшенные |
| --- | --- | --- | --- |
| T5, T11, T6 | 0.99–1.00 | T5 (гипотеза «температура реактора», открытый вопрос № 3) | T11, T6 |
| F19, F17, F26 | 0.96–1.00 | F26 (расход сырья, ок по справочнику) | F19, F17 |
| P22, P23 | 1.00 | P22 | P23 |
| T55, T48, T33, T71 | 0.97–0.99 | T55 (единственный явно поименованный выход печи П-3) | T48, T33, T71 |
| W70, F30 | 1.00 | W70 (массовый расход) | F30 |
| D10 | 99.99 % сентинелов | — | весь тег (мёртвый, [[02-clean-sentinels]] §6) |

Состав кластеров фиксируется в конфиге фич и в манифесте модели (`features`) — смена представителя
= переобучение и новая версия артефакта ([[08-model-artifact]]).

## 5. Возраст источников и наработка катализатора

- **`lims_age_h`** — возраст последнего замера ЛИМС к `sample_ts` (аналог `age_hours` из A.2,
  [[03-sync-freshness]] §4); **`pak_age_h`** — то же для ПАК. Модель должна знать, насколько
  свеж контроль: строки с большим возрастом — шире конформный интервал.
- **`cat_age_days`** — наработка катализатора. Якоря сброса — **просадки T5 апр-2024 и май-2026**
  (годовой режимный цикл: T5 среднее 371.3 (2023) → 331.8 (2024) → 369.9 (2025) → 335.9 (2026);
  T55: 382.8 → 347.4 → 380.9 → 356.2 — тот же рисунок у T6/T11/T12/T23):

```python
CAT_RESET_ANCHORS = ("2024-04-01", "2026-05-01")   # просадки T5 — регенерация/замена катализатора

def cat_age_days(ts: datetime, anchors=CAT_RESET_ANCHORS) -> float:
    """Дни с последнего якоря ≤ ts; 0–3 ч горизонт не влияет; фича монотонности (+1 в модели)."""
```

- Помечать как **модельное допущение**: официального подтверждения дат перегрузки катализатора нет.

## 6. Сезон и ВАК-фичи

- **Месяц/сезон** — sin/cos номера месяца (годовое исполнение ДТ: зимнее/летнее, цикл ±10–20 °C
  по всем температурным каналам); валидация по времени обязана видеть сезон.
- **ВАК T50/T90 как фичи** — исправленные формулы на ok-телеметрии:
  T50 = 44.625 + 10.0224·P13 + 0.06981·F9 + 0.471·T6; T90 = 162.998 + 0.12945·T12 + 59.57·(F15/2000)
  + 0.00036·W7 + 0.26366·T23 − 424.72638·F1/F26. Проверка на истории: T50 p5/мед/p95 = 253/**270**/279
  против ЛИМС 274; T90 = 325/**344**/351 против 331 — физичны и ложатся на лабораторные уровни.
- **CFPP с калибровкой смещения**: исправленная формула занижает систематически (−17.4 медиана
  против ЛИМС −6.2, ~+11 °C сдвига) → фича `cfpp_vak + 11.0` (смещение фиксируется в конфиге,
  помечено допущением).
- **T95/`GODT:D15`-члены с точкой ЛИМС не используются** (точка `24-2000.Pipeline` отсутствует,
  открытый вопрос № 1) — T95 предсказывает собственная модель[^t95]; CloudPoint-формула валидна
  по уровню и может идти фичей.

## 7. Анти-утечка на уровне признаков

> [!warning] Правила сборки строк
> 1. Все фичи — телеметрия и расчёты **строго до `sample_ts`** (окна/лаги заканчиваются в нём).
> 2. Таргет доступен строке только если `available_ts ≤ t_следующего решения`; для обучения строка
>    использует таргет ЛИМС, для валидации фичи не должны зависеть от значений после `sample_ts`.
> 3. `lims_age_h`/`pak_age_h` считаются от `available_ts` предыдущего замера — модель никогда не
>    «видит» свой будущий таргет через возраст.
> 4. Никакого перемешивания: строки идут по времени; сплиты делает 08-validation-timesplit с gap ≥ 3 ч.
> 5. Флаги не-ok внутри окон не выбрасываются молча: доля не-ok точек окна — фича, а «мертвые» окна
>    (вся телеметрия залипла) получают `null`-фичи и идут в строки с пониженным весом.

```python
def build_features(targets: list[QualityTarget], telemetry: pl.DataFrame,
                   lims: pl.DataFrame, pak: pl.DataFrame) -> pl.DataFrame:
    """Для каждого лабораторного замера: окна §2 + лаги §3 + дедуп §4 + возраст/наработка §5
       + сезон/ВАК §6 → quality_datasets/{target}.parquet (ts, target_value, features…, P4).
       Детерминировано; хэш выхода → datasets_manifest.json."""
```

[^t95]: Формула T95 не вычислима (точка `24-2000.Pipeline` отсутствует
    в выгрузке ЛИМС) → собственная модель T95; член формулы с ЛИМС критичен (~+80 °C).
