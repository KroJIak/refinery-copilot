# 01 — Инжест сырых выгрузок (`data/ingest.py`)

> [!note] Назначение
> Единственная точка чтения сырых файлов: телеметрия `data/raw/*.csv`, лаборатория
> и поточные анализаторы из `data/raw/*.xlsx`, справочник тегов (xlsx) из `data/raw/`. Результат —
> типизированный interim-кэш Parquet без какой-либо чистки: это следующий слой ([[02-clean-sentinels]]).
> Инжест не отбрасывает ни одной строки и не интерпретирует значения.

## Scope

**Содержит:** dtype-схемы и разбор форматов CSV (24-2000, АВТ) и XLSX (ЛИМС, ПАК); обработка
`Unnamed`-служебных колонок; нормализация времени в единый часовой пояс; регулярная 10-минутная
сетка как инвариант; таблица известных дублей каналов; кэш CSV→Parquet и хэши исходников.

**Не содержит:** замену сентинелов, детект заливаний/выбросов, синхронизацию источников,
построение признаков. Справочник КИП читается только как метаданные — истина о роли тега
определяется поведением значений (по результатам анализа истории данных).

| Источник | Файл | Форма | Период |
| --- | --- | --- | --- |
| Телеметрия 24-2000 | `data/raw/242000_tags.csv` (91 МБ) | 189 217 × 28: `date` + 26 тегов + 1 служебный индекс | 2023-01-01 00:00 → 2026-08-07 00:00 |
| Телеметрия АВТ | `data/raw/avt_tags.csv` (247 МБ) | 189 217 × 74: `date` + 71 тег + 2 служебных индекса | тот же |
| ЛИМС | выгрузка ЛИМС (xlsx) в `data/raw/` | 1 лист: 1 521 × 108, 6 блоков «точка отбора» | 2023-01-01 → 2026-08-09 |
| ПАК | выгрузка ПАК (xlsx) в `data/raw/` | 1 лист: 189 650 × 5 | 2023-01-01 → 2026-08-11 |
| Справочник | справочник тегов (xlsx) в `data/raw/` | листы КИП / ЛА / ПАК / ВАК | — (метаданные) |

> [!quote] Правило времени
> «Часовой пояс единый во всех источниках».

Следствие: инжест не выполняет конвертацию часовых поясов между файлами — только присваивает
единую зону (`timestamp[ms, UTC]`) и проверяет монотонность `date`.

## 2. Телеметрия CSV: правила разбора

1. **Сетка инвариантна.** Шаг ровно 10 минут, пропусков сетки нет (медиана = p99 = max = 10.0 мин);
   разность `date.diff()` проверяется assert'ом на каждой загрузке — ресемплинг не нужен.
2. **Пропусков нет, есть сентинелы.** Доля NaN по всем тегам 0.00 %; коды недостоверности
   {307, 251, 252, 240} вписаны прямо в значения и здесь **не трогаются** — только дальше ([[02-clean-sentinels]]).
3. **`Unnamed`-индексы.** Служебные колонки вида `Unnamed: 0`, `Unnamed: 1` — артефакты выгрузки
   (pandas-индекс), отбрасываются сразу с записью их имён в отчёт инжеста; данные не теряются.
4. **dtype-схема.** `date` → `datetime[ms, UTC]`; 26/71 тегов → `float64` (позже `float32` в Parquet);
   ничего не приводится к int — сентинелы смешаны с физическими значениями в одном столбце.
5. **Длинный формат при записи.** Для P4 столбцы разворачиваются в TagPoint-строки
   `tag_code, ts, value, quality_flag, source, unit` (канон A.1, api/data-models/01-timeseries.md);
   `tag_code` — dictionary-строка, партиционирование по году (data-store/02).

## 3. ЛИМС XLSX: правила разбора

- 1 521 строка × 108 колонок: **6 блоков «точка отбора»**, внутри блока — пары колонок
  (метка времени, значение) на показатель; итого **6 точек × показатели = 54 серии, ~35 тыс. замеров**.
- Строка 1 — название показателя, строка 2 — единицы, строка 3 — «Количество значений»;
  шапка многослойная → читается с `header=None` с последующей явной сборкой имён.

> [!quote] Правило единиц ЛИМС
> «Единицы в ЛИМС: строка единиц в файле содержит ошибки, ориентироваться на показатель
> в названии колонки».

Следствие: единица серии берётся из имени показателя по таблице соответствия
(напр. `95%.T → °C`, `Mg.Sulfur → мг/кг`, `D15 → кг/м³`), строка единиц сохраняется только для сверки.
- Замеры редкие и асинхронные: медианный интервал 24 ч; цетановое число — 42 замера (~29 суток),
  у PourPoint отбор-2 — 502 ч. Пробелы в сериях **легальны** — это ритм лаборатории, не дефект.
- Ключевая точка для целей: «Гидроочистка, отбор 2 (ДТ товарное)» — сера Mg.Sulfur, n = 1462.

## 4. ПАК XLSX: правила разбора

Фактическая раскладка нестандартна: заголовок колонки — имя анализатора,
в самой колонке — единицы + метки времени, **значения — в соседней `Unnamed`-колонке**.
Реальных серий две:

| Серия | Ед. | n | Покрытие | Особенности |
| --- | --- | --- | --- | --- |
| `24-2000:Mg.Sulfur` | ppm (= мг/кг) | 189 649 | полный период, шаг 10 мин, разрывов > 1 ч нет | max ровно 20.00 — зашкал (чистка в 02) |
| `24-2000:D15` | кг/м³ | 75 455 | только с 2025-03-05 10:20 | пустой диапазон 2023–2024 легален |

- «Unnamed: 2» пуста — других анализаторов в выгрузке нет; инжест это проверяет и фиксирует.
- ppm серы ПАК = мг/кг (массовая) — единицы при записи TagPoint: `мг/кг`.
- `24-2000:D15` (ПАК) соответствует точке «Гидроочистка, отбор 2»; метка времени ПАК — момент
  измерения анализатором (анти-утечка не требуется, задержки публикации ≤ 4 ч нет).

## 5. Справочник и дубли каналов

Справочник тегов инжестируется как таблица метаданных (код, описание, лист КИП/ЛА/ПАК/ВАК)
и **не** используется для интерпретации физической роли тега — по данным 17 из 26 кодов 24-2000
расходятся с описанием. Подтверждённый набор управляемых тегов:
P8/T11/F19 (24-2000); АВТ `crude_feed_rate_tph`, `avt_furnace_outlet_temp_c`,
`avt_column_pressure_mpa_abs`; блендинг — доли + присадка ≤ 3 %.

Дубли каналов, выявленные профилированием на этапе инжеста (детальная обработка — [[05-features]]):

| Кластер | Коды | r | Комментарий |
| --- | --- | --- | --- |
| Температуры 24-2000 | T5, T11, T6 | 0.99–1.00 | T11 по справочнику «расход сырья» — по данным температура |
| Расходы 24-2000 | F19, F17, F26 | 0.96–1.00 | F19 по справочнику «давление» — по данным расход |
| Давление верха К-2 | P22, P23 | 1.00 | рабочее ~1.08–1.18 МПа |
| Температуры печи АВТ | T55, T48, T33, T71 | 0.97–0.99 | T55 — единственный явно поименованный выход П-3 |
| Фр. 290–350 | W70, F30 | 1.00 | известное расхождение справочника |

## 6. Кэш CSV→Parquet и манифест

Сырые файлы в `data/raw/` неизменяемы. Инжест пишет interim-кэш и обновляет
`datasets_manifest.json` (data-store/06): `{path, sha256, rows, t_min, t_max, pipeline_version}` —
оттуда ядро берёт `data_hashes` для `RunReport` (P4).

```text
data/interim/242000__{yyyy}.parquet      # long-формат, value_raw, до чистки
data/interim/avt__{yyyy}.parquet
data/interim/lims.parquet                # sample_ts + value_raw по 54 сериям
data/interim/pak.parquet                 # 2 серии: Mg.Sulfur, D15
```

## 7. АВТ: теги и управляемые переменные

Теги КИП АВТ согласованы с данными — расхождение только W70 (массовый расход фр. 290–350,
по данным W70 ≡ F30, r = 1.00). Управляемые АВТ на схемах помечены «Y»:
`crude_feed_rate_tph` (расход нефти), `avt_furnace_outlet_temp_c` (температура выхода печи),
`avt_column_pressure_mpa_abs` (давление колонны). В CSV явно поименованных выходов печей нет —
только T55 (выход П-3, FIRC2470); **таблица соответствия «английское имя ↔ короткий код» не выдана**
(открытый вопрос № 2) — сопоставление восстанавливается по схемам
заводские схемы (pdf) из `data/raw/` и хранится в конфиге инжеста, не в коде.

```json
{"pipeline_version": "0.1.0", "sources": {
    "242000_tags.csv": {"sha256": "e3b0c4…", "rows": 189217, "tags": 26, "grid_min": 10.0, "dropped_cols": ["Unnamed: 0"]},
    "avt_tags.csv":    {"sha256": "7d865e…", "rows": 189217, "tags": 71, "grid_min": 10.0, "dropped_cols": ["Unnamed: 0", "Unnamed: 1"]},
    "lims": {"series": 54, "points": 35000, "t_min": "2023-01-01T00:00:00Z", "t_max": "2026-08-09T00:00:00Z"},
    "pak":  {"series": ["24-2000:Mg.Sulfur", "24-2000:D15"], "pak_sulfur_rows": 189649, "pak_d15_since": "2025-03-05T10:20:00Z"}},
 "interim": {"files": ["data/interim/242000__{yyyy}.parquet", "data/interim/avt__{yyyy}.parquet",
                       "data/interim/lims.parquet", "data/interim/pak.parquet"]}}
```

Отчёт пишется рядом с interim-кэшем и дублирует ключевые поля в `datasets_manifest.json` —
единственное место, откуда `RunReport.data_hashes` берёт хэши исходников (P4).

> [!example] Инварианты инжеста (проверяются на каждом запуске)
> 1. Число строк CSV = 189 217 на каждый файл; шаг сетки ровно 10 мин.
> 2. ЛИМС: 54 серии, каждая с `sample_ts` в 2023-01-01…2026-08-09; дубликатов (точка, показатель, ts) нет.
> 3. ПАК: сера покрывает весь период; D15 начинается 2025-03-05 10:20.
> 4. Хэши исходников в манифесте совпадают с фактическими — иначе пайплайн падает, а не читает чужие данные.
> Идемпотентность: повторный запуск над теми же raw-файлами даёт те же хэши кэша.
