# 02 — Маска сентинелов, залипания, выбросы (`data/clean.py`)

> [!note] Назначение
> Первая содержательная ступень пайплайна: превращает сырые значения из interim-кэша в физические
> значения + флаги достоверности. Ничего не удаляет физически: каждая точка остаётся в Parquet
> со своим `quality_flag`, а `value` сентинелов становится `null`. Никакая метрика, фича или модель
> не считается до завершения этой ступени.

> [!quote] Правило маски сентинелов
> «Пропусков в телеметрии нет — вместо них сентинелы 307/251/252/240 (у Q21 — 2.97 %, у Q20 —
> 11.65 %, у D10 — 100 %: тег мёртв). Первая ступень любого пайплайна — маска сентинелов».

## Scope

**Содержит:** маску сентинелов {307, 251, 252, 240} → `null` + `quality_flag=sentinel`;
детектор залипающих серий (T18, W4/W10, F17/F22/F25, F5/F26/P52/F57 и др.); зашкалы-потолки;
различение «сентинел 307 у Q21 vs реальный выброс»; исключение мёртвого тега D10; правила Hampel-
маски для физически невозможных значений (параметры самого Hampel/PCA — в [[04-anomaly-params]]).

**Не содержит:** синхронизацию источников и freshness ([[03-sync-freshness]]), обучение детектора
аномалий, расчёт признаков, любое удаление строк из Parquet.

## 1. Маска сентинелов — шаг 1

Множество кодов: **{307, 251, 252, 240}**[^sent]. Точное равенство значения коду (с допуском на float,
`abs(v − код) < 1e-6`) → `value = null`, `quality_flag = sentinel`. Применяется безусловно, ко всем
тегам, до любых других проверок — иначе сентинел попадает в статистику и ломает пороги.

Доли точек-сентинелов (по истории данных):

| Источник | Теги с высокой долей | Значения |
| --- | --- | --- |
| 24-2000 | Q20 — **11.65 %** (код 307), T12 — 4.56 %, Q21 — 2.97 %, F2 — 2.88 %, T16 — 1.76 %, F17 — 1.54 %, F19/F9 — 1.23 %, T23 — 0.77 %, F14 — 0.33 % | остальные < 0.1 % |
| АВТ | D10 — **99.99 %** (мёртвый тег), F26 — 37.62 %, T39 — 10.2 %, F28 — 4.89 %, F27 — 2.07 %, F34/F3/F14 — 2–3.3 % | остальные 0–2 % |

Сентинелы почти всегда идут длинными сериями (см. §2) — факт «длина серии» сохраняется в отчёте
чистки и попадает на страницу «Репортёр данных» (frontend/16).

## 2. Залипающие серии → `stuck`

Детектор: длина максимальной серии подряд идущих одинаковых значений (после маски сентинелов);
серия ≥ 2 ч (12 шагов по 10 мин) помечает точки флагом `stuck`[^stuck]. Максимальные серии в сырых
данных: Q20 — 17 293 точки (~120 суток), T18 — 6 660, W4/W10 — 2 868, F9 (24-2000) — 2 299;
АВТ: F26 — 63 333, D10 — 119 879 (весь сентинел), T39 — 3 834.

**Залипания после удаления сентинелов** (теги, которые остаются «константными» и без сентинелов):

| Теги | Доля точек в сериях ≥ 2 ч | Особенность |
| --- | --- | --- |
| T18 (24-2000) | 6.7 % | плюс потолок значений 99.99 — зашкал |
| W4, W10 (24-2000) | 2.5 % / 1.8 % | оба зашкалены на 10.0 |
| F15, F22, F17, F25 (24-2000) | 2.5–4.6 % | большие расходы, замирают |
| F5, F26, P52, F57 (АВТ) | 7.5 % / 6.8 % / 4.7 % / 4.2 % | F57 дополнительно 4.08 % нулей |

## 3. Потолки-зашкалы

Насыщение диапазона датчика — отдельная причина брака, не совпадающая с сентинелами:

| Тег | Потолок | Трактовка |
| --- | --- | --- |
| W4, W10 (24-2000) | ≤ 10.0 | зашкал перепада/расхода |
| T18 (24-2000) | ≤ 99.99 | зашкал (и не давление по справочнику) |
| Q21 (24-2000) | ≤ 24.90 | см. §4 — отказ/зашкал анализатора серы |
| ПАК `24-2000:Mg.Sulfur` | ≤ 20.00 | зашкал анализатора |

Правило: точки в ε-окрестности потолка (точное плато) → `value = null`, `quality_flag = stuck`;
значения просто вблизи потолка, но с вариацией — остаются с флагом `ok` и пометкой в отчёте.

## 4. Q21: сентинел 307 vs плато 24.9 vs реальный выброс

> [!quote] Факт по Q21
> «Q21 — содержание серы на выходе гидроочистки, ppm; значение ~307 в ряде — **выброс**».

По истории данных у Q21 различаются **три** вида брака — правило различения:

| Явление | Признак | n | Действие |
| --- | --- | --- | --- |
| Сентинел 307 | точное значение 307, длинные серии (max run 4 441 точки ≈ 31 сутки) | 5 618 (2.97 %) | → `null`, `sentinel` (шаг 1) |
| Плато 24.9 | **ровно** 24.9 блоками по 144 точки/сутки на 107 днях (напр. 20–22.04.2024, 02.09.2024, 16–21.04.2026) | 5 420 (2.95 %) | → `null`, `stuck` (зашкал анализатора, не реальная сера) |
| Реальные превышения | (10, 12] — 16 564 точки по 980 дням (рабочий режим «чуть выше 10»); (12, 15] — 2 615; (15, 20] — 417 точки по 86 дням | ~19 600 | остаются со значением; Hampel/PCA могут пометить часть как `outlier` |

Дискриминатор «сентинел vs реальный выброс»: **сентинел — точное совпадение с кодом из множества
{307, 251, 252, 240}** (часто серией), **реальный выброс — физически невозможное значение, уникальное
по величине**. Не превращать всю область (20, 25] в сентинелы: именно плато-равенство 24.9 отличает
зашкал от реального выброса. После чистки Q21 (n = 183 599): медиана 8.46, p5–p95 = 5.1–9.7;
реальных превышений 10 мг/кг ≈ 10.7 % точек. Сигнал Q21 согласован с ПАК по уровню (поточечно r = +0.41).

## 5. Физически невозможные значения → `outlier`

После удаления сентинелов остаются хвосты — в основном при пусках/остановах:

- отрицательные значения у расходов и давлений: F19 min −5.03 (p1 −0.12), F9 min −20.24, P8 min −3.80 (p1 0.01), P2/P22/P44 — отрицательные минимумы, F65 min −4.93 (p1 20.96);
- пики сверху: P8 max 7.0 при p99 0.24 (×30 выше p99), P22 max 313 при p99 1.24, T55 max 417.3 при p99 386.2, F5 max 6212 при p99 407.

Правило маски на этой ступени (детектор Hampel + PCA T²/SPE, обученный офлайн, — [[04-anomaly-params]]):

```python
def flag_outliers(frame: pl.DataFrame, tag_cfg: TagConfig) -> pl.DataFrame:
    """1) жёсткий фильтр: value <= 0 для расходов/давлений → outlier;
       2) маска 'установка в работе' (T5 > 300 °C для 24-2000) — вне её точки → outlier;
       3) помечает точки по порогам Hampel/PCA из artifacts (фит — 04-anomaly-params)."""
```

Точки не удаляются: `value = null` или значение сохраняется — флаг `outlier` исключает их из фич
и метрик, оставляя улику для страницы «Репортёр данных».

## 6. Мёртвый тег D10 — исключение

D10 (плотность обессоленной нефти, АВТ): **99.99 % точек — сентинелы** (максимальная серия 119 879
точек — весь сентинельный диапазон). Плотность нефти по телеметрии фактически отсутствует.

- В Parquet D10 публикуется как остальные теги (все точки `sentinel`) — честный след исходника.
- Из набора признаков моделей D10 **исключается** ([[05-features]]); вместо него плотность сырья
  берётся из ЛИМС/ПАК D15-серий.
- Замена плотности в формулах ВАК/моделях — через `GODT:D15`-члены с точкой ЛИМС или ПАК-серию
  (ограничение: ПАК D15 только с 05.03.2025, [[01-ingest-csv]] §4).

## 7. Схема флагов и псевдокод ступени

`quality_flag` — канон enum B.7: `ok / sentinel / stuck / outlier / missing`.
Приоритет присвоения: `sentinel` → `stuck` (потолок/серия) → `outlier` (Hampel/PCA/физика) → `ok`.

```python
SENTINELS = {307.0, 251.0, 252.0, 240.0}

def clean(frame: pl.DataFrame, cfg: CleanConfig) -> pl.DataFrame:
    """Порядок шагов (фиксирован, нарушение = баг):
       1. mask_sentinels: {307,251,252,240} → null + quality_flag='sentinel'
       2. detect_stuck: серии одинаковых значений ≥ 2 ч и ε-плато у потолков
          (10.0 W4/W10 · 99.99 T18 · 24.9 Q21 · 20.0 ПАК) → 'stuck'
       3. flag_outliers: физика (value ≤ 0), маска 'в работе', пороги Hampel/PCA → 'outlier'
       4. mark_dead_tags: теги с долей sentinel > 99 % → исключены из фич (список в отчёте)
       Возвращает frame без удаления строк; пишет cleaning_report.json (доли флагов, серии)."""
```

> [!warning] Инвариант ступени
> В Parquet на выходе слоя **нет ни одного значения из {307, 251, 252, 240} вне флага `sentinel`**;
> все последующие слои обязаны фильтровать `quality_flag = 'ok'` (или явно учитывать `stuck/outlier`)
> перед любой агрегацией. Никаких «магических чисел» дальше по пайплайну не существует —
> сентинелы не проходят наружу ([[data-pipeline/00-OVERVIEW]], правило 2).

[^sent]: Коды «недостоверного значения», вписанные в поток вместо пропусков — почти всегда
    длинными сериями.
[^stuck]: Залипание = датчик замирает: серия одинаковых значений длиннее времени отклика процесса.
    Доля таких точек — признак качества канала в отчёте чистки.
