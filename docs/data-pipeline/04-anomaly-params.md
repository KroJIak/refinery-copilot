# 04 — Параметры Hampel и PCA T²/SPE (`models/anomaly_fit.py`)

> [!note] Назначение
> Обучает **офлайн** статистический детектор аномалий входных данных: Hampel-фильтр по каждому тегу
> + PCA-модель с метриками T² (Хотеллинг) и SPE (квадрат невязки). Продукт — **параметры и пороги**,
> а не скоринг: они экспортируются в `artifacts/models/` и используются (а) офлайн при сборке
> признаков — второй проход по истории, (б) в рантайме агентом данных core-architecture/03
> (протокол P5/P3 по данным).

> [!quote] Состав детектора
> Детектор аномалий входных данных: «Hampel-фильтр + PCA T²/SPE» — фича домена data-pipeline.

## Scope

**Содержит:** выборку «чистой истории» для фита; Hampel: окно, медиана, MAD, порог per-тег;
PCA: стандартизация, число компонент, пределы T²/SPE; экспорт параметров в артефакты с хэшами
данных; детерминизм фита.

**Не содержит:** рантайм-скоринг точек (делает core-architecture/03-agent-data), решение об отказе
(`sensor_fault`/`out_of_training_domain` — оркестратор), чистку сентинелов/залипаний ([[02-clean-sentinels]]),
расчёт признаков ([[05-features]]).

## 1. Вход: чистая история

Фит выполняется на истории после ступени [[02-clean-sentinels]]:

- только точки с `quality_flag = 'ok'` (сентинелы, залипания, зашкалы уже вынесены в `null`);
- только режим «установка в работе» — маска T5 > 300 °C (24-2000), иначе пуски/остановы
  захватываются в «норму» и пороги размываются (по истории данных хвосты — в основном при
  пусках/остановах);
- признаки для PCA — рабочие телеметрические каналы (T5/T6/T11, F19/F17/F26, P13, T55 и др.),
  дедуплицированные кластеры r ≥ 0.96 ([[05-features]] §4) — дубли не должны задваивать дисперсию.

## 2. Hampel-фильтр: параметры per-тег

Правило Hampel: значение-выброс, если |x − median(W)| > `z_thr` · MAD(W) в окне W; MAD = 1.4826·
median|xᵢ − median(W)|. Фитует по каждому тегу отдельно на сетке 10 мин:

| Параметр | Дефолт | Комментарий |
| --- | --- | --- |
| `window` | ±18 шагов (±3 ч) | не больше горизонта задержки 0–3 ч |
| `z_thr` | 3.5 | консервативно: реальный режимный сдвиг ±10–20 °C не должен ловиться как выброс |
| `min_history` | 1008 точек (7 суток) | теги с меньшей чистой историей не филтруются (только PCA/физика) |

```python
def fit_hampel(history: pl.DataFrame, cfg: HampelConfig) -> dict[str, HampelParams]:
    """Per-тег: {window, z_thr, med, mad} по 'ok'-точкам в рабочем режиме.
       Теги с потолками/залипаниями (W4/W10, T18, Q21, F26...) получают params с флагом
       'ceiling_guard' — их выбросы уже закрыты масками 02, Hampel не переоткрывает."""
```

## 3. PCA: метрики T² и SPE

- Стандартизация каналов (median/MAD вместо mean/std — устойчивость к хвостам);
- `n_components` — по порогу объяснённой дисперсии 0.95 (фиксирован в конфиге, не перебирается);
- **T²** (Хотеллинг): xᵀPΛ⁻¹Pᵀx; предел — эмпирический p99.9 по обучающей истории (или F-распределение,
  фиксируется в конфиге);
- **SPE** (Q-невязка): ‖(I−PPᵀ)x‖²; предел — по Jackson–Mudholkar или эмпирический p99.9.

Смысл пары: T² ловит «редкое сочетание внутри модели», SPE — «состояние вне модели» — последний
прямо питает причину отказа `out_of_training_domain` в рантайме (решение принимает оркестратор,
не пайплайн).

```python
def fit_pca(history_std: pl.DataFrame, cfg: PcaConfig) -> PcaParams:
    """P, Λ, mean/mad-центры, t2_limit, spe_limit, список каналов (порядок = константa версий)."""

def export_anomaly_params(hampel: dict, pca: PcaParams, out: Path) -> ArtifactManifest:
    """artifacts/models/anomaly-params/{version}/params.json + sha256 данных фита;
       проверка воспроизводимости: повторный фит на тех же данных → байт-в-байт params.json."""
```

## 4. Экспорт и потребители

```text
artifacts/models/anomaly-params/
  ├── params.json          # hampel per-тег + pca (каналы, компоненты, пределы) + version
  └── manifest.json        # sha256 обучающей выборки, диапазон дат, pipeline_version
```

| Потребитель | Протокол | Как использует |
| --- | --- | --- |
| data-pipeline ([[05-features]]) | P4, внутренний | второй проход по истории: точки выше пределов → `quality_flag = outlier` в `quality_datasets/` |
| core-architecture/03 (агент данных) | P5 + P3 | рантайм-скоринг текущего окна на `t_point`; флаги → вход в отказ `sensor_fault`/`out_of_training_domain` |
| data-store/06 | P4 | params.json попадает в каталог артефактов, версии в `datasets_manifest.json` |

> [!warning] Границы ответственности
> 1. Пайплайн **фитует и экспортирует**, ядро **скорит** — в рантайме никаких фитов и обучения
>    (ядро никогда не обучает в рантайме).
> 2. Решение об отказе принимает оркестратор core-architecture/10; детектор только поставляет
>    флаг/метрику (`t2`, `spe`, `hampel_z`).
> 3. Параметры версионируются жёстко: смена состава каналов или порогов = новая версия каталога,
>    старые артефакты не перезаписываются (правило data-store).

## 5. Контракт рантайм-скоринга (реализует core-architecture/03)

Пайплайн экспортирует параметры, ядро — скорит. Граница фиксируется сигнатурой, которую
core-architecture/03-agent-data выполняет над текущим окном телеметрии на `t_point`:

```python
def score_window(window: pl.DataFrame, params: AnomalyParams) -> AnomalyVerdict:
    """Окно ≤ 3 ч ok-телеметрии → {per_tag: {hampel_z}, t2, spe, flags: list[QualityFlag]}.
       Только чтение params.json; никакого фита; результат — в output агента данных (AgentStep)."""
```

Интерпретация результатов детектора в терминах причин отказа (решение принимает оркестратор
core-architecture/10, детектор только поставляет метрики):

| Наблюдение | Флаг | Кандидат-причина отказа |
| --- | --- | --- |
| Hampel-выброс по ключевому каналу | `outlier` | `sensor_fault` |
| Серия/зашкал по ключевому каналу | `stuck` | `sensor_fault` |
| SPE выше предела (состояние вне модели) | `outlier` | `out_of_training_domain` |
| T² выше предела | `outlier` | `out_of_training_domain` |
| Всё в пределах | `ok` | — |

## 6. Проверка качества фита

Фит без валидации запрещён: перед экспортом считается отчёт на отложенном хвосте истории
(последние 90 дней, не участвуют в фите):

- доля точек, помеченных детектором на «нормальном» хвосте (без пусков/остановов) — целевой
  порядок < 0.5 % (ложные срабатывания);
- воспроизведение известных событий: сентинел-серии и пусковые хвосты ([[02-clean-sentinels]] §5)
  должны ловиться — иначе пороги слишком свободные;
- T²/SPE-пределы проверяются на «рабочем» окне маски (T5 > 300 °C): пределы не должны отсекать
  штатные сезонные сдвиги ±10–20 °C.

Отчёт фита пишется рядом с params.json и включается в `metrics.json` (P4).

Пример экспортируемого артефакта:

```json
{"version": "ap-0.1.0", "pca": {"channels": ["T5", "F26", "P13", "T55", "F65"], "n_components": 3,
  "t2_limit": 9.21, "spe_limit": 4.87, "variance_explained": 0.95},
 "hampel": {"24-2000.T5": {"window": 18, "z_thr": 3.5, "med": 354.0, "mad": 12.1},
            "24-2000.F26": {"window": 18, "z_thr": 3.5, "ceiling_guard": true}},
 "fit_data_sha256": "e3b0c442…", "fit_range": {"start": "2023-01-01T00:00:00Z", "end": "2026-05-10T00:00:00Z"}}
```

## 7. Детерминизм

- Фит полностью детерминирован: медианы/MAD, PCA (полный SVD, без случайных инициализаций),
  эмпирические перцентили — сид не нужен, но `SEED` из env всё равно фиксируется в манифесте
  для единообразия ([[data-pipeline/00-OVERVIEW]], правило 5).
- Порядок каналов в params.json фиксирован (sorted) — порядок строк не влияет на хэш.
- Единственность: один активный `anomaly-params` на версию пайплайна; смена = новая запись манифеста.
